# DeepFuzz 项目计划（Plan）

版本：V0.1  
日期：2026-01-29  
假设：12 周交付 MVP + Beta

---

## 1. 目标与范围

### 目标
- 交付可运行的 DeepFuzz MVP：支持至少 2 类核心网协议黑盒 fuzz。  
- LLM 能生成测试套与变异策略，并完成一次完整测试闭环。  
- 支持结果监控与报告生成。

### 范围
参考《DeepFuzz 需求设计说明书》，以 **协议模板 + LLM策略 + 可控环境** 为核心。

---

## 2. 里程碑计划（12 周）

### Phase 0：需求与协议调研（第 1-2 周）
**交付物**  
1. 需求基线冻结（V0.1）  
2. 核心协议优先级列表（如 NAS / PFCP / GTPv2）  
3. 受控测试环境方案（沙箱/模拟网元）

---

### Phase 1：框架搭建（第 3-4 周）
**交付物**  
1. 项目管理与任务调度骨架  
2. Multi-Agent 基础框架（Orchestrator / Strategy / Monitor）  
3. Fuzz Runner 原型（可执行固定测试套）

---

### Phase 2：协议模型与测试套生成（第 5-6 周）
**交付物**  
1. 协议 Profile 框架（字段/状态机/约束）  
2. LLM 生成测试套能力（结构化输出）  
3. Seed Corpus & 场景库

---

### Phase 3：变异策略引擎（第 7-8 周）
**交付物**  
1. 字段/结构/状态变异策略引擎  
2. 策略权重与组合调度  
3. 可重复执行的测试集

---

### Phase 4：监控与异常归因（第 9-10 周）
**交付物**  
1. 运行监控（崩溃/超时/协议违规）  
2. 异常分类与复现包归档  
3. 事件流与可观测性

---

### Phase 5：报告与交付（第 11-12 周）
**交付物**  
1. 问题单与报告生成（Markdown/PDF/JSON）  
2. Dashboard 基础视图  
3. MVP 验收与 Beta 发布

---

## 3. 工作流与任务分解（Workstreams）

### 3.1 平台与基础设施
- 任务编排与队列  
- 运行调度与并发控制  
- 统一配置与权限控制

### 3.2 LLM/Agent 工作流
- Strategy Agent：测试套生成、策略生成  
- Monitor Agent：异常归因与复现  
- Prompt 模板与上下文管理

### 3.3 协议与语义建模
- 协议 Profile（字段/状态机/约束）  
- 协议适配器与序列化/解析器

### 3.4 Fuzz 执行引擎
- 变异策略引擎  
- 多目标调度  
- 失败重试与回退

### 3.5 监控与报告
- 运行指标  
- 异常归档  
- 问题单输出

### 3.6 安全与合规
- 授权环境校验  
- 测试沙箱隔离  
- 审计日志

---

## 4. MVP 验收标准

1. 至少支持 **2 个核心网协议** 的黑盒 fuzz。  
2. LLM 可生成可执行的测试套与变异策略。  
3. 能捕获异常并形成可复现报告。  
4. 支持在受控环境中运行并监控结果。  

---

## 5. 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 协议复杂度高 | 误报/漏报 | 引入协议专家模板 + 状态机约束 |
| LLM 输出不稳定 | 策略不一致 | 结构化模板 + 版本化提示词 |
| 黑盒可见性不足 | 归因困难 | 加强监控、流量归档 |
| 环境不可控 | 合规风险 | 严格隔离与授权校验 |

---

## 6. 下一步建议（可选扩展）

- 增加白盒/灰盒覆盖率反馈  
- 支持更多协议与厂商实现  
- 引入自动修复建议与再测试闭环  

---

**备注**：计划与范围可根据资源与优先级调整。
